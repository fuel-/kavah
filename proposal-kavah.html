Kavah — Project Proposal

Phase 1  ·  Web App

What We’re Building

Kavah is a curated audio scripture experience — not a Bible app, not a devotional app. Think of it like a faith-based music streaming platform: users open the app and scripture begins playing immediately, with a warm AI voice reading hand-selected NKJV verses organized into thematic playlists. The team curates which verses surface, creating an intentional, immersive experience that feels personal rather than encyclopedic.

Phase 1 is a free, mobile-first web app that launches quickly, builds the user base, and establishes the API foundation before the Phase 2 native iOS and Android app.

Phase 1 Feature Set

Immersive Audio Player
  • Auto-play on open — scripture starts immediately, no setup required
  • Full verse text displayed on screen while audio plays (hear and read simultaneously)
  • Player controls: play, pause, next, previous, shuffle, repeat (single-verse loop for memorization)
  • Warm, natural AI voice via ElevenLabs TTS
Curated Content
  • NKJV scripture via licensed Bible API — team curates which verses surface
  • Verses tagged by theme (peace, faith, healing, love, strength, and more)
  • Category filtering so users find what they need
Discovery
  • Search by verse reference or keyword within the curated library
Accounts & Community Building
  • Email / magic link authentication — no password required
  • Email capture: waitlist prompt for the upcoming native app, building the launch list
  • “Get the App” persistent CTA promoting the Phase 2 native experience
  • Optional donation feature for users who want to support the app
Analytics
  • Play counts, listen duration, popular categories and verses (internal dashboard)
Content Management (Admin)
  • Simplified CMS for the team: verse entry, ElevenLabs audio generation or manual upload, category tagging, publish / unpublish

How the Key Pieces Work

The Player Experience

Users land on the home screen and audio begins immediately — no tapping required. The verse text is displayed in Lora Italic while ElevenLabs’ warm voice reads it aloud. Controls let them repeat a verse for memorization, skip forward, or shuffle through the playlist. Categories let them filter by what they need in the moment.

Curated Content — Not a Bible Browser

The full NKJV lives in the backend. The team uses the CMS to hand-select which verses surface to users, generate audio for each one via ElevenLabs, tag categories, and publish. Users only ever see the curated library — intentional, not encyclopedic.

The Admin CMS

A clean internal interface gives the team full control: browse the NKJV, select a verse, generate audio with one click, preview the result, tag categories, set position in playlists, and publish. Audio can also be manually uploaded if preferred. No engineering required for content updates.

How Users Sign In

Magic link authentication — users enter their email, receive a secure sign-in link, and they’re in. No password to forget, no friction. Sessions persist comfortably so users aren’t re-prompted constantly.

Building the Native App Audience

Phase 1 is the runway for Phase 2. A waitlist capture prompt invites engaged users to join the early list for the native app. A persistent “Get the App” banner keeps it front of mind. On launch of Phase 2, we have a warm list ready to convert.

Donations

An optional giving flow lets users support the app via Stripe. Clean, unobtrusive — available but not pushed. Donation history is tracked per account when signed in, but guests can donate too.

Audio Delivery

Audio files are generated by ElevenLabs and stored in AWS S3. CloudFront delivers them via CDN-based streaming — smooth playback on any mobile connection, anywhere in the world.

What’s Not in Phase 1 Scope

The following are Phase 2 items, explicitly out of scope for this engagement:

  • Native iOS and Android apps (React Native)
  • Background audio and lock screen controls
  • Note-taking per verse
  • Paid subscription / Apple IAP / Google Play Billing
  • Additional ElevenLabs voices
  • Spanish language support
  • Push notifications

The Phase 1 architecture is designed from day one to carry these forward without rebuilding.
